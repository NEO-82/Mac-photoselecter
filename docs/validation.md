- [ ] 느린 폴더 열거 중 폴더 전환, RAW 디코딩 중 다른 폴더 선택 시 이전 결과 배제
- [ ] 외장 드라이브 해제 후 오류 안내, 앱 생존, 재연결 후 재선택/새로고침 가능
- [ ] JPEG EXIF 방향 1~8, 세로 ARW의 프리뷰/RAW 방향과 확대 위치 일치
- [ ] 여러 화면/배율 및 앱 비활성화 후 확대 상태가 고착되지 않음

실제 ARW 샘플은 사용자 소유/배포 허용 파일로 준비합니다. 카메라 모델, 펌웨어, ARW 압축 방식, 원본 픽셀 크기, macOS 버전, 프리뷰 유무/크기, RAW 성공 여부를 기록하세요.

## 누른 채 사진 넘기기 — 회귀 확인

2026-11-08 [macOS 빌드 실행 #2](https://github.com/NEO-82/Mac-photoselecter/actions/runs/42475958754)에서
소스 커밋 `fa4cc89d6bbe3c9f4283fe4aef41424b26bc9ab0`의 기존 XCTest 5개와 추가 4개, 총 9개가 통과했습니다.
arm64 Release 빌드와 DMG 무결성/서명 검증이 통과했고, 새 DMG의 GitHub 다운로드 및 체크섬 일치도 확인했습니다.

추가 XCTest는 NSEvent를 구성해 AppKit 이벤트 핸들러를 직접 호출하고 캔버스의 실제 그리기 결과를 확인합니다.
누름/해제, 좌우 반복 92회(양끝 포함), ARW/JPEG 디코더 출력 교체, 버튼 해제 후 늦은 이미지 교체, Esc를 다룹니다.
형식별 이미지는 테스트용 CGImage이며 실제 ARW 디코딩이나 물리 마우스·키보드의 시스템 전달을 검증하지는 않습니다.

실제 MacBook에서는 다음을 확인합니다.

1. JPG와 지원되는 ARW가 섞인 폴더에서 사진을 엽니다. 왼쪽 버튼을 누른 채 오른쪽/왼쪽 방향키를 번갈아 누르고 길게 눌러 반복합니다.
2. 각 전환 뒤에도 100% 확대가 유지되고, 첫/마지막 사진에서 더 이동하려 해도 확대가 풀리지 않는지 확인합니다.
3. 버튼을 놓는 즉시 화면 맞춤으로 돌아오는지 확인합니다. 느린 ARW 로딩/고해상도 처리 도중에도 버튼을 놓아 보고 완료 후 다시 확대되지 않는지 확인합니다.
4. 누름/해제와 폴더 재선택을 반복하고 Esc 및 앱 전환 시에는 기존처럼 확대가 해제되는지 확인합니다.

## 측정 프로토콜

동일한 1,500장 세트를 내장 SSD, 외장 SSD, 외장 HDD에서 각각 실행합니다.
저장장치 모델/연결 방식, 사진 수/해상도/형식 비율, OS 버전, 프로세스 메모리를 함께 기록합니다.
OS 파일 캐시가 남은 재실행과 최초 앱 캐시 미스는 구분하고, 미측정 콜드 I/O 수치를 주장하지 않습니다.

Console에서 subsystem `dev.photoselect`, category `navigation`의 `preview/full`, `cacheHit`, `latencyMs` 로그를 수집합니다.
이 시간은 요청부터 메인 큐 결과 수신까지이며 화면 합성/실제 표시 완료 시간은 포함하지 않습니다.
캐시 적중 전환의 목표는 100ms 이내이며 보장값이 아닙니다. Instruments의 Time Profiler/Hangs, Allocations/VM Tracker와 화면 기록으로 실제 화면 갱신 및 메인 스레드 정지를 별도 확인합니다.

각 전환 범주 100회 이상, RAW 확대 20회 이상을 기록하고 연타 후 30초 대기 시 메모리가 반복 탐색마다 증가하는지 확인합니다.

## FastStone과 비교할 조작감

실제 FastStone과 나란히 확인한 결과는 아직 없습니다.
