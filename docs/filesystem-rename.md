# v0.7.1 — 저장장치 이름 변경 안전성·진단 보완

**테스트한 macOS exFAT 드라이버에서 자동 일괄 이름 변경 지원은 미완료입니다.** 원본 안전성 조건을 충족하는 우회를 확인하지 못해 변경 전에 중단합니다. APFS/HFS+의 기존 기능을 유지하며, 지원 여부 검사와 실패/복구 보고를 보완합니다.

[Apple Silicon용 v0.7.1 빌드80 안전 보완판 DMG](https://github.com/NEO-82/Mac-photoselecter/raw/e478343efe85dcc2c74eff9590881e740aacf528/downloads/J-S-0.7.1-arm64.dmg) · macOS 13+, M1 이상

**이 파일은 exFAT 자동 이름 변경 지원 완료판이 아닙니다.** 원본 변경 전 안전 중단과 진단·복구 상태 보고를 개선한 설치본입니다.

## 확인된 원인

v0.7.0은 첫 임시 이름을 만들 때 `renamex_np(..., RENAME_EXCL)`을 사용합니다. macOS CI의 exFAT 디스크 이미지에서 빈 목적 이름으로 이 호출을 실행하면 **NSPOSIXErrorDomain 45 (ENOTSUP)**가 발생했습니다. 사용자 보고의 내부 저장장치 성공·exFAT 실패와 같은 조건입니다.

기존 이름이 목적지에 이미 있을 때는 exFAT도 EEXIST(17)를 반환합니다. 따라서 충돌 오류만 확인해서 해당 볼륨의 독점 이름 변경을 지원한다고 판단하면 안 됩니다. 새 코드는 빈 목적지로 실제 이름 변경, 기존 목적지 거부, 파일 식별자/바이트 유지, 원래 이름 복원까지 작은 전용 검사 파일로 확인합니다.

v0.7.0의 ‘복구’ 표시는 첫 변경 호출이 실패해 모든 파일이 처음부터 원래 이름에 있었을 때도 나올 수 있었습니다. v0.7.1은 실행 전 중단·현재 원래 이름·현재 새 이름·임시 이름·위치 불명을 구분합니다.

## 처리 방식과 안전 한계

| 환경 | 처리 |
|---|---|
| APFS/HFS+ 등 지원 볼륨 | 커널의 `renamex_np(RENAME_EXCL)` 유지 |
| 기본 호출이 ENOTSUP/EOPNOTSUPP/ENOSYS인 경우 | 같은 폴더 FD를 사용하는 `renameatx_np(RENAME_EXCL)`을 검사 |
| 두 독점 API를 지원하지 않는 볼륨 | 사진 변경 전 중단. 원본을 복사·삭제하거나 일반 rename으로 우회하지 않음 |
| 읽기 전용/권한 오류 | 중단. 지원 여부 오류로 간주해 다른 API를 시도하지 않음 |
| 명시적으로 영구 파일 ID를 지원하지 않는 볼륨 | 재연결 후 저널 복구를 보장할 수 없어 중단 |
| 실행 중 위치를 확인할 수 없는 경우 | 성공/복구로 표시하지 않고, 태그 변경을 보류하고 기존 저널 보존 |

파일 시스템 이름으로 무조건 허용하지 않습니다. 실제 볼륨의 statfs/getattrlist 정보, 실제 독점 연산 결과 및 식별자 검사를 사용합니다. 검사 파일은 별도 UUID 이름의 숨김 디렉터리에 만들고 정리하며 사용자 사진은 검사 재료로 쓰지 않습니다.

확인한 exFAT 드라이버는 `exclusiveRename=false`, `persistentFileIDs=false`, `hardLinks=false`를 보고했습니다. `renamex_np(RENAME_EXCL)`, `renameatx_np(RENAME_EXCL)` 및 링크 대안 모두 빈 목적지에서 ENOTSUP(45)를 반환했습니다.

### 제외한 우회

격리된 이미지에서 `FSRenameUnicode`는 일반적인 충돌 검사와 단순 이름 변경은 통과했습니다. 그러나 서로 다른 두 파일이 같은 이름으로 동시에 변경되는 시험에서 **둘 다 성공을 반환**했습니다. 이 후보는 배포 코드에서 제거했습니다. 같은 실험에서 재연결 후 파일 식별자를 이용한 복구도 실패했습니다. [폐기한 후보의 격리 시험 기록](https://github.com/NEO-82/Mac-photoselecter/blob/e2833ab9b3212df559ac1f74008e196d00da265d/downloads/filesystem-ExFAT-results.xml).

`fileExists` 확인 후 일반 rename, 일반 이동 API의 숨은 복사/삭제 경로, 기존 대상 삭제 후 변경, 원본 내용 복사 후 원본 삭제는 사용하지 않습니다. 현재 확인한 API로 exFAT의 원자적 독점 이름 변경을 안전하게 구현했다고 주장하지 않습니다.

## 유지한 작업 흐름

전체 대상 및 비대상 이름 충돌 검사, Unicode/대소문자 검사, 선택 범위, 현재 정렬 순서, ARW/JPG 독립 처리, 확장자 유지, 작업 직전/각 원본 변경 직전 상태 재검사를 유지합니다. 같은 폴더의 UUID 임시 이름 → 최종 이름 2단계와 기존 버전 1 저널·복구·롤백·태그 연결을 유지합니다.

실패 보고에는 파일 시스템·실제 호출 방식·오류 도메인/번호·실제 시도한 임시/최종 이름을 포함합니다. 부분 변경이면 파일별로 검증된 현재 위치를 표시합니다. 위치를 재검증하지 못하면 이전에 기억한 경로를 현재 위치로 보고하지 않고 태그도 추측한 경로로 다시 쓰지 않습니다. 상세 오류는 결과 문구의 툴팁으로도 확인할 수 있습니다.

RAW 추출·이미지 파이프라인·뷰어 확대/삭제·다중 선택·정렬·태그 필터·앱 이름과 아이콘의 소스는 변경하지 않았습니다. 이름 변경 창의 기존 구성은 유지하며 결과 문구만 보완했습니다.

## 실물 저장장치 확인 절차

새 버전의 물리 저장장치 검증은 미실행입니다. 검증용 사진 사본 폴더에서 파일명·바이트 해시·태그를 기록하고 진행하세요. 앱의 이름 변경 구현이 원본 복사/삭제로 우회한다는 의미는 아닙니다.

1. APFS 내부/외장, HFS+ 외장, exFAT 외장 각각 디스크 유틸리티에서 형식과 읽기·쓰기 상태를 확인합니다.
2. 현재 폴더 전체 및 선택 파일만 범위에서 미리보기·정렬·ARW/JPG 독립 번호·충돌 거부를 확인합니다.
3. 지원 볼륨에서 변경 후 모든 파일의 바이트 해시와 태그를 비교합니다. 비선택 파일명/내용이 그대로인지 확인합니다.
4. 현재 CI와 같은 exFAT 미지원 결과가 나오면 ‘실행 전 중단’과 파일 변경 0개를 확인하고, 반복 실행으로 우회하려 하지 마세요. exFAT 지원 완료로 판정하지 않습니다.
5. 연결 해제/쓰기 오류 시험은 검증용 매체에서 수행하고, 위치 불명과 저널 보존이 표시되는지 확인합니다. 원래 장치를 다시 연결한 후 복구 시에도 실제 파일명/내용/태그를 비교합니다. 불명확한 파일을 영구 삭제하거나 저널을 임의로 지우지 마세요.
