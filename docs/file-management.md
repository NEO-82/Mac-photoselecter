# J♡S v0.6.0 — 대량 사진·정렬·일괄 이름 변경

v0.5.5의 이미지 표시·색 변환·확대 구현을 유지하면서 대량 목록 관리, 세 가지 사진 정렬, 현재 폴더 전체 사진의 일괄 이름 변경을 추가했습니다. 안정 버전은 [`stable-v0.5.5-before-file-management`](https://github.com/NEO-82/Mac-photoselecter/tree/stable-v0.5.5-before-file-management) 태그로 복원할 수 있습니다. [v0.5.5 검증 자료](../downloads/v0.5.5-build48/)와 기존 DMG도 보존했습니다.

## 사용 방법

목록 상단의 **파일 이름순·촬영 시간순·크기순** 버튼을 누르세요. 같은 버튼은 ↑/↓를 전환하며 다른 기준은 ↑부터 시작합니다. 선택 사진을 유지하고 썸네일·큰 보기·태그 필터의 탐색 순서에 같은 정렬을 적용합니다. 폴더와 일반 파일의 위치와 탐색 방식은 유지합니다. 정렬과 필터 전환은 태그를 저장하거나 이미지 캐시를 초기화하지 않습니다.

- 이름은 숫자를 고려한 자연 정렬입니다. RAW/JPG는 별도 항목입니다.
- 촬영 시간은 ImageIO의 EXIF DateTimeOriginal, 없으면 DateTimeDigitized를 사용합니다. 파일 생성·수정 시각과 TIFF 편집 시각은 대체 값으로 쓰지 않습니다. 시간이 없으면 양방향 모두 뒤쪽, 같은 시간이면 파일명 오름차순입니다. 시간대가 없으면 카메라의 기록 시각을 같은 기준으로 비교합니다.
- 크기는 실제 바이트 수이며 동률은 파일명 오름차순입니다.

촬영 정보는 이미지 디코딩 없이 백그라운드에서 읽고 크기·수정 시각과 함께 캐시합니다. 분석 중 기존 순서를 보여 주고 완료된 정렬을 한 번 적용합니다. 폴더 전환이나 새 요청은 오래된 결과를 적용하지 않습니다.

도구바의 **일괄 이름 변경**을 열고 기본 이름, 구분 문자, 시작 번호, 자릿수(1–12)를 입력하세요. 미리보기의 대상 수·정렬 방향·기존 이름·예정 이름·충돌 상태를 확인한 뒤 **이름 변경 실행**을 누릅니다. 입력 중 계산은 백그라운드에서 수행하며 최신 결과가 준비될 때까지 실행을 막습니다. 미리보기는 가상화된 표로 표시합니다.

대상은 **현재 폴더의 모든 지원 사진**입니다. 태그 필터와 숨김 표시 설정에 관계없이 숨김 사진도 포함합니다. 하위 폴더, 문서, 심볼릭 링크, macOS `._` 메타데이터 파일은 제외합니다. XMP 등 별도 사이드카 파일도 변경하지 않습니다. 현재 정렬 방향대로 RAW/JPG 구분 없이 연속 번호를 부여하고 확장자의 대소문자까지 유지합니다. 예를 들어 `Wedding`, `_`, `1`, `4`는 `Wedding_0001.ARW`, `Wedding_0002.JPG`가 됩니다. 자릿수보다 큰 번호는 자르지 않습니다.

실행 전에는 사진 파일이나 태그를 변경하지 않습니다. 실행 중에는 충돌할 수 있는 폴더 이동·정렬·태그·삭제 조작을 막고 진행 단계와 개수를 표시합니다. 종료 요청은 진행 작업과 태그 저장을 기다립니다.

## 파일과 태그 보호

실행 직전에 전체 대상 집합, 볼륨, 파일 식별자, 확장자와 이름 충돌을 다시 확인합니다. 기존 파일을 덮어쓰지 않는 macOS `renamex_np(RENAME_EXCL)`로 같은 폴더 안에서만 이동합니다. 사진 데이터는 쓰거나 복사하거나 삭제하지 않습니다. 이름 교환도 고유한 숨김 임시 이름을 거쳐 처리합니다.

먼저 `~/Library/Application Support/dev.photoselect.app/rename-journals/`에 원래 이름·새 이름·임시 이름·파일 식별자·관련 태그 스냅샷을 원자적으로 기록하고 동기화합니다. 작업 잠금으로 앱의 중복 실행 간 동시 이름 변경을 막습니다. 최종 파일 위치와 태그 저장을 확인한 뒤에만 완료 기록을 정리합니다.

중간 실패 시 원래 이름으로 되돌립니다. 되돌리기도 실패하면 실제로 확인한 파일 위치에 맞춰 태그를 연결하고 복구 기록을 남깁니다. 디스크를 다시 연결하고 해당 폴더에서 **일괄 이름 변경**을 열면 **중단 작업 복구** 안내가 나옵니다. 모두 새 이름인 작업은 태그 저장을 마무리하고, 부분 적용된 작업은 원래 이름으로 복구합니다. 다른 볼륨이나 다른 파일을 덮어쓰지 않습니다. 기록 또는 태그 JSON이 읽히지 않으면 새 파일 작업을 중단하고 오류를 표시합니다. 실패 중 생성된 다른 파일도 덮어쓰지 않습니다.

복구 전에는 `.J-S-rename-…` 파일이나 복구 JSON을 직접 지우지 마세요. 외부 프로그램에서 동시에 같은 파일을 편집·이동하는 작업은 피하세요. 같은 실제 파일을 가리키는 여러 하드 링크가 대상이면 모호한 복구를 방지하기 위해 거부합니다. 독점 이름 변경을 지원하지 않는 파일 시스템에서는 오류를 보고하며 복사·삭제 방식으로 우회하지 않습니다. 실제 전원 차단·모든 외장 파일 시스템에 대한 내구성을 보증한 것은 아닙니다.

Bundle Identifier `dev.photoselect.app`, 기존 `tags.json` 경로·버전1 JSON 형식, 사용자 설정 구조는 유지합니다. 태그 경로는 일괄 원자 저장으로 갱신하며 이름 교환에서도 연쇄 치환하지 않습니다. 태그 저장 실패 시 파일명도 복구하고 재시도할 기록을 남깁니다. 정상 완료 후 이름이 바뀐 경로로 태그·필터·최근 이미지/썸네일/메타데이터 캐시를 함께 연결합니다.

## 대량 목록과 기존 표시 성능

폴더 열거·정렬·촬영 정보 분석·이름 변경은 비동기로 처리합니다. 화면에 필요한 썸네일과 현재/앞뒤 표시 이미지만 준비하는 기존 구조를 유지합니다. 3,000개 원본 비트맵을 미리 디코딩하지 않습니다. v0.5.5의 바이트 예산 LRU, 선택 이미지 고정, 방향별 프리페치, 진행 중 동일 이미지 작업 공유, 오래된 완료 결과 차단과 마지막 정상 프레임 유지도 그대로 사용합니다.

메모리 압박 후 캐시 예산은 정상 상태 알림까지 축소된 상태를 유지합니다. 폴더 전환·종료 시 불필요한 요청을 취소하고 종료 시 캐시를 정리합니다. 이름 변경 때는 작업을 중지한 뒤 캐시의 경로 키를 동시에 옮겨 최근 사진을 재디코딩하지 않도록 합니다. 화면 색 변환, ARW JPEG 추출기, 확대 입력/좌표는 변경하지 않았습니다.

## 실기기 확인이 필요한 범위

CI는 Intel macOS/Xcode에서 실행하고 배포 앱은 arm64로 교차 빌드합니다. 이번 새 버전의 **M1 Pro 16GB 실사용, 2,000–3,000개 서로 다른 실제 RAW/JPG의 내장/외장 SSD 탐색, 장시간 메모리 추이, 물리 드라이브 분리·권한 거부·전원 차단, 실제 입력/디스플레이의 프레임 표시**는 확인하지 못했습니다. v0.5.5에서 두 SSD의 개선과 블랙아웃 해소는 사용자의 실기기 보고이며 이번 버전의 새 측정으로 취급하지 않습니다.

동일한 실제 촬영 폴더에서 최초 열기, 끝까지 스크롤,20장 순방향/10장 역방향, 필터와 세 가지 정렬, 태그를 포함한 이름 변경·재실행을 확인하세요. 외장 드라이브 실패 복구 검사는 원본 보관본이 있는 복사 폴더로 진행하고 Activity Monitor의 장시간 메모리와 화면 녹화를 함께 기록해야 합니다. CI 수치를 M1 Pro/실제 SSD 처리량으로 일반화하지 않습니다.
