## 확대 설정과 변경 코드

**보기 → 클릭 유지 확대 배율**에서 100~200%를 10% 간격으로 선택합니다. 기본값은 100%이며 `UserDefaults`의 `clickZoomPercent`에 저장합니다. 기존 태그 파일, Bundle Identifier, 테마 설정, 앱 이름과 공식 아이콘을 유지합니다.

100%는 표시 JPEG의 한 픽셀이 디스플레이의 물리 픽셀 하나를 차지하는 기존 계산입니다. 150%는 그 표시 크기의 1.5배, 200%는 2배입니다. 현재 창의 backing scale을 적용하며, 커서의 이미지 상대 위치를 유지하고 빈 공간이 드러나지 않도록 경계를 제한합니다. 200%는 표시 확대이며 새로운 이미지 세부 정보나 센서 해상도를 생성하지 않습니다.

- `App.swift`: 기존 보기 메뉴에 배율 하위 메뉴와 JPEG 픽셀 기준 안내 추가.
- `PhotoModel.swift`: 선택값 검증·저장·복원과 배율 계산 추가.
- `Viewer.swift`: 실제 그리는 JPEG 크기에만 배율 적용. RAW 현상·AI 확대·새 이미지 캐시를 추가하지 않음.
- `Browser.swift`: 선택 메뉴 체크 표시, 열린 뷰어 재그리기와 현재 배율 HUD 갱신.
- 테스트: 11개 배율의 실제 렌더링 크기, 1/1.5/2 배율 디스플레이 계산, 커서 위치, 설정 복원, 메뉴, 누른 채 Delete·다음 사진·놓기 검사 추가/확장.

마우스 누름 판별 시간, 드래그, 놓기, 더블클릭, Escape, 방향키, 태그, 휴지통 처리 코드는 유지했습니다. 기존 `ImagePipeline`과 최대 Sony 내장 JPEG 추출·ICC/색 관리 경로도 유지했습니다.

## exFAT: 원인과 남은 작업

`renamex_np(RENAME_EXCL)`과 `renameatx_np(RENAME_EXCL)`은 테스트한 exFAT에서 비어 있는 목적 이름으로 이동할 때 `ENOTSUP(45)`를 반환합니다. 목적 이름이 이미 존재하면 EEXIST가 나오므로 충돌 거부만으로 지원을 판정할 수 없습니다. 볼륨은 독점 rename·하드 링크·영구 파일 ID 미지원을 보고했습니다.

사용자가 알려 준 **macOS 27.0.1**의 Apple Silicon CI에서도 같은 exFAT API 실패를 재현했습니다. 과거의 catalog API 대안도 동시 목적지 경쟁과 재연결 복구 검증에 실패한 기록이 있습니다. [v0.7.1 원인·안전 한계](filesystem-rename.md)를 참조하세요.

이번 변경에서 `BatchRename.swift` 엔진은 바꾸지 않았습니다. 일반 rename의 사전 존재 확인만으로 다른 프로그램의 동시 파일 생성을 막을 수 없으며, 복사 후 삭제나 안전장치 제거로 우회하지 않았습니다. **안전한 exFAT 대체 경로는 아직 확보하지 못했습니다.**

| 파일 시스템 | 현재 동작과 검증 범위 |
|---|---|
| APFS | 기존 독점 rename 유지. 바이트·수정 시간·태그·선택 범위·충돌/동시 경쟁·롤백/저널·재연결 복구 검사 |
| HFS+ | APFS와 같은 검사 |
| exFAT | 변경 전 중단. 원본 이름·바이트·태그 보존 및 이미지 재연결 후 원본 보존 검사. **성공적인 이름 변경 검증이 아님** |

읽기 전용, 권한 오류, 장치 분리, 위치 불명 시 기존 중단·저널 보존·태그 변경 보류를 유지합니다. 실물 SSD/HDD/SD 카드의 새 버전 검증은 미실행입니다.

## 빌드87 자동 검증과 계측

[macOS 빌드 #87](https://github.com/NEO-82/Mac-photoselecter/actions/runs/43712255259), 소스 `35f61f3d919ef28f25c12243d4c8a3c45283fd4e`, 설치 파일/결과 `f829d76883e0d6ea22840e7801aecead1d8fb14b`. Intel macOS 15/Xcode 16.4에서 arm64 설치본을 교차 빌드했습니다.

| 검사 | 결과 |
|---|---|
| 전체 macOS XCTest | 140개 통과, 실패·오류·건너뜀 0 |
| APFS/HFS+/exFAT 이미지 | 각 7개 통과. exFAT은 안전 중단 검사 |
| 실제 Sony RAW Release | 4개 통과 |
| Release 3,005장 선택 성능 | 1개 통과, 95백분위 8.75ms, 드래그 중 큰 미리보기 요청 0 |
| RAW 캐시 적중 적용 | 최대 15.87ms, 첫 이미지 이후 빈 draw 0 |

이름 변경 시간은 ARW/JPG 확장자의 **작은 합성 시험 파일**로 측정했습니다. 시험 파일 생성·사후 전체 바이트 비교는 시간에서 제외하고, 엔진의 사전 확인·2단계 rename·저널·태그 처리는 포함합니다. 실제 RAW 1,200장 또는 물리 SSD 성능으로 해석하지 않습니다.

| 파일 수 | APFS | HFS+ |

exFAT은 각 파일 수에서 변경 0개이며 처리 시간은 이름 변경 성능 수치가 아닙니다. 기존 368개 원본 보존 검사에는 실제 Sony A7M4 1개와 소형 합성 파일 367개가 포함됩니다.

## 실기기에서 남은 확인

1. macOS 27.0.1 Mac에서 기존 앱을 종료하고 설치합니다. 기존 tags.json과 사용자 설정은 삭제하지 않습니다.
2. 사진 사본으로 각 배율을 선택하고 재실행 후 설정을 확인합니다. Retina/외부 모니터에서 커서 위치·드래그·놓기·방향키·태그·더블클릭·Escape를 확인합니다.
3. 확대를 누른 채 Delete → 다음 사진에서 확대 유지 → 놓기 흐름과 실제 macOS 휴지통 이동을 확인합니다.
4. APFS/HFS+ 시험용 사진 사본에서 선택/전체·충돌·태그·내용 해시와 수정 시간을 비교합니다. 원본 매체를 분리하는 실패 시험은 하지 마세요.
5. 현재 exFAT은 지원 완료판이 아닙니다. 사본에서도 변경 전 중단과 원본 보존을 확인하는 범위이며 성공적인 자동 변경을 기대하지 마세요.
6. 실제 2,000~3,000장 촬영 폴더·장시간 메모리·실물 외장 매체와 실제 입력 장치 검증은 별도입니다.
