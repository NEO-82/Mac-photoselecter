# v0.7.4 파일 복사 개발 및 검증

이 문서는 새 복사 기능의 구현과 검증 범위를 기록합니다. 실제 macOS 빌드·Finder 연동·외장 장치 검증 전에는 배포 완료를 의미하지 않습니다. 현재 확인된 배포는 v0.7.3 빌드93입니다.

## 사용 흐름

- 가운데 목록에서 파일/폴더를 클릭합니다. ⌘클릭·⇧클릭으로 혼합 다중 선택합니다. 기존 ⌘A와 사각형 선택은 표시된 사진을 대상으로 유지합니다. 태그 필터에서 ⌘A를 사용하면 태그 사진만 선택됩니다.
- 편집 → 파일 복사(⌘C)는 표준 파일 URL을 클립보드에 기록합니다. Finder에서 ⌘V를 사용하면 Finder가 복사를 수행합니다.
- Finder에서 복사한 파일/폴더를 J♡S의 현재 폴더에 ⌘V로 붙여넣습니다. 대상 전체 경로가 진행 창에 표시됩니다.
- 목록에서 드래그하면 선택한 파일/폴더 전체를 복사로 제공합니다. 외부/앱 내부 세션 모두 `.copy`만 광고하고 modifier에 따른 이동으로 변경하지 않습니다. 드래그 종료에서 원본을 지우는 코드는 없습니다.
- Finder 또는 J♡S에서 왼쪽 트리의 폴더, 가운데 폴더 항목, 현재 목록의 빈 영역으로 드롭합니다. 상태 줄의 전체 대상 경로와 네이티브 드롭 강조를 확인합니다. 일반 파일 위 또는 폴더가 확정되지 않은 트리 영역에는 놓을 수 없습니다.
- 비동기 단일 복사 작업의 항목 수·검증 중인 전송 바이트를 표시하고 취소할 수 있습니다. 완료 창에 성공 경로와 실패/건너뜀·부분 결과·임시 데이터 경로를 표시합니다. 원본 선택과 탐색은 유지하며 복사 중 새 이름 변경/휴지통 작업을 차단합니다. 이미 시작한 이름 변경/휴지통 작업이 있으면 복사를 시작하지 않습니다.

## 안전 범위와 비용

`FileCopyEngine`은 원본을 읽기 전용/NOFOLLOW로 엽니다. 소스 경로에 write, rename, remove를 호출하지 않습니다. 한 작업 내 파일 순서는 직렬이며 이미지 디코딩 큐·캐시를 사용하지 않습니다. 데이터 버퍼는 1 MiB입니다. 이름 변경 엔진과 v0.7.3 복구·동의·SHA-256 경로는 변경하지 않습니다.

대상 폴더에 독점 생성한 숨김 임시 폴더에서 데이터를 기록하고, 원본 크기/변경 시각/파일 ID와 복사본 SHA-256을 검사합니다. 파일 내용의 EXIF는 바이트 그대로 복사하고 `copyfile(COPYFILE_METADATA)`로 정상 메타데이터를 복사합니다. 실패 시 완료로 표시하지 않습니다. 원본 폴더와 심볼릭 링크 대상/자기 하위 폴더, 심볼릭 링크 및 특수 파일은 거부합니다. 패키지는 하위 폴더 전체를 복사합니다. 깊이는 128 미만으로 제한합니다.

완료한 임시 결과는 `renamex_np(RENAME_EXCL)`로 독점 공개합니다. 해당 API 미지원 시(exFAT 등) 최종 위치에 `mkdir` 또는 `open(O_CREAT|O_EXCL|O_NOFOLLOW)`로 파일/폴더를 각각 독점 생성하고 다시 복사·검증합니다. 일반 rename이나 덮어쓰기 fallback은 없습니다. **호환 경로는 최종 이름으로 기록되는 동안 부분 결과가 보이며, 폴더 전체가 원자적으로 나타나지 않습니다.** 중단/오류 시 최종 부분 결과를 자동 삭제하지 않습니다. 진단용 임시 폴더도 경로와 함께 보존할 수 있습니다. 대상 내용을 확인하고 필요 없는 임시 데이터만 직접 정리하세요.

대소문자/Unicode 정규화 충돌과 `._파일명` 충돌은 보수적으로 건너뜁니다. 이 검사는 안내를 위한 것이며 경합 시 실제 덮어쓰기 방지는 EXCL API가 담당합니다. 기존 폴더와 병합하지 않으며 자동 이름 변경도 하지 않습니다. 원본의 짝 있는 AppleDouble 파일은 독립 파일로 복제하지 않고 copyfile 메타데이터 경로를 사용합니다. 고아 AppleDouble 또는 단독 AppleDouble 선택은 실패로 보고합니다. APFS/exFAT의 실제 xattr/리소스 포크 차이는 별도 디스크 테스트가 필요합니다.

NSFileCoordinator는 참여하는 프로세스를 조정합니다. 비참여 앱의 동시 원본 쓰기, 경로 교체, 장치 분리를 원자적으로 차단하는 것은 아닙니다. 검사 시점에 확인한 스냅샷만 보장하며 진행 중 폴더를 다른 앱에서 수정하지 마세요. 매 파일의 크기·내용을 검증해도 전체 디렉터리가 한 시점의 스냅샷이라는 보장은 없습니다.

기본 경로의 디스크 비용은 원본 읽기 + 임시 쓰기 + 검증 재읽기입니다. 호환 공개는 임시 읽기 + 최종 쓰기 + 최종 검증 재읽기가 추가되어 대략 데이터 크기의 6배 I/O가 발생합니다. 검증을 생략하지 않습니다. 진행 바이트는 처음 임시 결과를 만드는 데이터 바이트이며 전체 디스크 I/O 또는 남은 시간 추정값이 아닙니다. 사전 항목 수 계산 중에는 준비 상태를 표시합니다. 실제 대용량 RAW 처리량·최대 메모리는 아직 측정하지 않았습니다.

태그는 원본 경로의 앱 전용 JSON에 유지되고 파일 데이터에 기록하지 않습니다. 앱이 생성한 복사본 경로의 과거 태그만 제거합니다(하위 파일 포함). 태그 저장 실패는 별도 오류로 보고하고 이후 새 복사를 차단합니다. Finder가 외부에서 수행한 복사는 J♡S의 완료/검증/태그 정리 범위가 아닙니다. Finder 붙여넣기 성공, modifier 드래그, 다른 앱의 파일 URL 처리 결과는 macOS 실기기에서 확인해야 합니다.

## 자동 검증

`swift test --filter FileCopyTests`에 신규 사례를 추가했습니다. 원본 바이트·수정 시각, RAW/JPG/문서, 하위 폴더/패키지, 기존 파일/폴더 보존, 대소문자/Unicode/AppleDouble 충돌, 자기 복사·하위 폴더·심볼릭 링크, 잘못된 대상, 취소, 최종 공개 직전 경합, 미지원 독점 rename 호환 경로, 일부 실패 후 다음 파일, 14/100/1,000개 작은 파일, 표준 파일 URL 및 앱 태그 불변을 검사합니다. 작은 합성 파일 시간은 실제 RAW/외장 장치 성능을 나타내지 않습니다.

현재 Linux에서 패키징 도구 대역 테스트 `python3 scripts/test-packaging.py` 9개와 Bash 구문·diff 검사를 통과했습니다. macOS XCTest와 앱 빌드는 Linux에서 실행할 수 없습니다. 새 XCTest는 macOS에서 실행하기 전까지 미검증입니다. 이 문서의 테스트 목록을 통과 결과로 해석하지 마세요.

## macOS 실제 검증 절차

1. 기존 태그·설정 JSON을 백업하고 테스트용 APFS 및 exFAT 폴더를 준비합니다. 촬영 원본 대신 검증용 복제본을 사용합니다. 사전 원본/대상 파일 목록, 크기, SHA-256, 메타데이터를 기록합니다.
2. `bash scripts/validate-macos.sh`로 기존 회귀와 새 테스트를 모두 실행합니다. `.github/workflows/package-macos.yml`의 실제 Sony RAW Release 4개·3,005장 선택 성능·볼륨별 이름 변경/복구 검사도 유지합니다.
3. ARW/JPG/일반 파일 혼합 1/14/100/1,000개, 빈/중첩/패키지 폴더를 J♡S→Finder(⌘C/⌘V 및 드래그), Finder→J♡S(⌘V 및 세 드롭 위치), J♡S 내부에서 복사합니다. 태그 필터 선택·폴더 혼합 선택·원본 선택/스크롤·정확한 대상 강조를 확인합니다. Option/Command 등의 modifier를 바꾸어도 J♡S가 제공한 드래그가 이동되지 않는지 원본 경로/해시로 검사합니다. Finder가 소유한 복사는 Finder의 오류/완료와 실제 대상 해시로 별도 검증합니다.
4. APFS↔APFS, 내부 SSD↔exFAT, 서로 다른 외장 SSD에서 크기/SHA-256/EXIF/xattr/리소스 포크와 원본 태그·설정 JSON 불변 및 복사본 미태그를 확인합니다. 실제 SSD가 없으면 디스크 이미지 검사와 실물 검사를 구분합니다.
5. 중복 이름/폴더/정규화 차이, 다른 앱의 동시 같은 이름 생성, 쓰기 권한 부족, 읽기 오류, 용량 부족, 취소, 장치 해제를 각각 유발합니다. 기존 대상 해시와 원본 해시가 유지되고 실패/건너뜀·부분 경로·미처리 항목을 구분하는지 확인합니다.
6. 복사 중 이전/다음·검은 화면·클릭 유지 확대·100~200%·+/-·태그·정렬을 사용합니다. 복사 중 이름 변경/휴지통은 차단되고 종료 요청은 복사 중단과 태그 쓰기를 기다리는지 확인합니다. 완료 후 확대 중 Delete, 범위 선택, 태그 필터, 이름 변경·휴지통, 앱 재시작 확대 100%와 기존 아이콘/앱 이름을 확인합니다.
7. 실물 exFAT SSD의 이름 변경은 기존 동의·호환 경로·저널을 그대로 사용합니다. 실패 시 볼륨/API/오류/저널을 수집하며 검증 없이 새 이름 변경 엔진으로 교체하지 않습니다.
8. 검증 결과와 결함을 기록한 뒤 `PHOTOSELECT_BUILD_NUMBER=<새 번호> bash scripts/package-macos.sh`로 arm64 Release·서명·마운트·DMG SHA-256을 검증합니다. 업로드된 실제 v0.7.4 DMG를 다시 내려받아 해시를 대조한 후에만 새 설치 파일로 안내합니다.
