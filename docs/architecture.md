# 동작과 자원 설계

## 스레드와 취소

AppKit 상태 갱신은 메인 큐에서 수행합니다. 폴더 열거/정렬은 사용자 우선순위 전역 큐에서 실행합니다.
사진 표시/프리페치는 foreground 1개와 speculative 1개 큐를 사용하며 썸네일은 별도 최대2개 큐로 실행합니다.
현재 사진을 우선 요청하고 탐색 방향 두 장과 반대 방향 한 장을 준비합니다. 탐색마다 유효한 이웃 작업 전체를 취소하지 않습니다.
겹친 프리페치/표시 요청은 같은 디코딩을 공유하고 우선순위를 올립니다. 취소 티켓은 해당 UI 구독만 취소합니다.
표시 세대 UUID와 캐시 epoch로 오래된 결과를 배제하며, 캐시가 있으면 동기 조회로 바로 표시해 중간 빈 화면을 피합니다.
썸네일 재사용 시 구독을 취소하고 URL 및 폴더 세대를 확인합니다. 파일 읽기·추출·JPEG 디코딩·색 변환은 백그라운드에서 처리합니다.

ImageIO JPEG 디코딩이 이미 시작되면 강제 중단할 수 없습니다. 유효한 완료 결과는 캐시에 남기고 취소된 UI에는 전달하지 않습니다.
아직 시작하지 않은 취소된 썸네일은 디코딩을 건너뜁니다. 폴더 열거도 강제 중단하지 않지만 과거 결과는 반영하지 않습니다.

디스플레이 LRU는 물리 메모리의1/8(최대1.5GiB), 썸네일 LRU는96MiB이며 둘 다256항목 한도도 적용합니다. 비용은 bytesPerRow×height입니다.
현재 선택 비트맵은 UI와 동일한 객체를 따로 고정하며 이 캐시 예산 밖입니다. 압축 JPEG 데이터는 파이프라인마다128MiB 바이트 한도로 제한합니다.
메모리 warning/critical에서 선택 이미지 외 캐시와 불필요한 대기 작업을 해제하고 정상 알림까지 비트맵 예산을1/4로 유지합니다.
현재 비트맵·실행 중 디코더/색 변환 버퍼·GPU 메모리도 있어 이 수치는 프로세스 전체 메모리 상한이 아닙니다.
폴더 전환/새로고침/볼륨 변경에서 캐시를 비우고 epoch를 바꿉니다. 실시간 외부 파일 변경은 새로고침으로 반영합니다. 정렬/태그 필터는 캐시를 유지하며 일괄 이름 변경은 기존 비트맵·압축 소스·메타데이터 캐시 키를 새 경로로 옮깁니다.

## Retina의 100%

**실제로 디코딩한 JPEG 1픽셀 = 디스플레이 물리 픽셀 1개**로 정의합니다.
backingScaleFactor=2이면 원본 6000×4000 이미지는 3000×2000 AppKit 포인트 크기로 그립니다.
따라서 1픽셀=1포인트 방식의 Retina 2배 확대와 다릅니다. RAW 프리뷰의 실제 JPEG 크기를 사용하며 더 큰 센서 메타데이터 크기로 부풀리지 않습니다. RAW 맞춤 보기도 실제 물리1:1 이상으로 늘리지 않습니다.

버튼을 누른 위치를 화면 맞춤 이미지의 정규화 좌표로 변환하고 그 원본 위치가 커서 아래로 오도록 확대합니다.
드래그 위치에 따라 이 좌표를 다시 계산합니다. 가장자리에서는 빈 영역이 나타나지 않도록 이동 범위를 제한합니다.
뷰보다 작은 이미지는 중앙에 위치하므로 가장자리 커서 고정이 제한됩니다.
좌우 방향키는 버튼 누름 상태를 유지한 채 사진만 바꿉니다. 커서 위치는 다음 사진의 좌표 계산에도 사용합니다.
이미지 교체 자체는 누름 상태를 변경하지 않습니다. 로딩 중 버튼을 놓으면 일반 보기로 돌아가며,
늦게 도착한 표시용 JPEG도 일반 보기로 그립니다. 확대를 이유로 다른 원본이나 RAW 현상 결과로 교체하지 않습니다.
버튼 해제, Esc, 앱 비활성화 시 확대 상태를 해제합니다.
디스플레이 해상도 스케일링과 모니터 이동에 따른 체감 선명도는 Mac 실기기에서 확인해야 합니다.

## ARW 경로와 정확도

1. `EmbeddedPreview`가 TIFF의 연결된 IFD/SubIFD/Exif/Sony MakerNote에서 가장 큰 완전한8비트 DCT JPEG를 찾습니다. JPEGInterchangeFormat(513/514)을 첫 발견에서 끝내지 않습니다.
2. 8비트 RGB/YCbCr JPEG strip만 프리뷰 후보로 조사합니다. CFA/비8비트 센서 strip과 SOF3 lossless Bayer 타일은 제외합니다. 실제 A7M4에서36MB 불필요 탐색을 방지합니다. 잘못된 범위·순환·과다 파싱은 제한합니다.
3. 추출한 카메라 JPEG만 ImageIO로 디코딩합니다. 센서 데이터를 현상하거나 썸네일을 RAW 센서 크기로 확대하지 않습니다. 충분한 프리뷰가 없으면 제한/실패를 알립니다.
4. JPEG ICC가 우선이며 JPEG Exif 및 바깥 ARW의 ExifColorSpace/Interop(R03 AdobeRGB 등)을 존중해 명시적 sRGB로 변환합니다. JPEG에 ICC가 없다고 곧바로 sRGB로 단정하지 않습니다. 정보가 전혀 없으면 sRGB 가정임을 디코딩 메타데이터에 기록합니다.
5. 썸네일은 같은 JPEG의 주 이미지를 축소하고 동일한 색 변환을 거칩니다. `.preview`와 `.full`은 같은 표시 비트맵/캐시 키를 뜻합니다. 더 이상 `.full`이 RAW 렌더링을 뜻하지 않습니다.
6. `DecodedImage.sourceSize`는 실제 JPEG 픽셀 크기, `sensorSize`는 별도 메타데이터입니다. ARW의 `fullResolution`은 JPEG와 센서의 해상도 일치 여부이며 false라고 RAW 렌더링을 요청하면 안 됩니다. 작은 JPEG에서는100%도 JPEG 실제 픽셀일 뿐 RAW 센서100%가 아니며 초점 판별 한계를 표시합니다.

UI의 마우스 확대·더블클릭·ESC·방향키·태그/휴지통 흐름은 유지합니다. 실제 Sony A7M3/A7M4와 합성 TIFF/JPEG 회귀 검증 자료는 [안정 프리뷰 검증](stable-preview.md)에 있습니다.
모든 Sony 변형을 지원한다고 주장하지 않습니다. JPEG가 충분하지 않은 파일을 RAW 현상으로 자동 대체하지 않습니다.

## 파일 접근

NSOpenPanel에서 선택한 루트 URL의 security scope를 획득하고 하위 폴더 작업과 디코딩 작업이 lease를 보유합니다.
폴더를 바꿔도 완료되지 않은 디코딩이 scope를 잃지 않게 합니다. startAccessing 실패가 곧 파일 접근 거부를 뜻하지는 않으므로 실제 읽기 결과를 사용합니다.
macOS 개인정보 보호/TCC 거부나 장치 해제는 읽기 오류로 처리합니다. 예외를 삼키고 성공으로 표시하지 않습니다.
영구 북마크가 없으므로 앱 재시작 시 사용자가 폴더를 다시 선택해야 합니다.


## 탐색·태그·휴지통

왼쪽 폴더 트리는 홈·데스크탑·이 Mac·저장장치 루트를 노출하고 펼친 폴더만 비동기로 읽습니다.
가운데는 현재 폴더 전체 사진의 가상화된 그리드, 오른쪽은 선택 사진의 화면 맞춤 미리보기입니다.
오른쪽 미리보기와 큰 사진 창은 같은 이미지 파이프라인/디코딩 결과를 공유합니다.
큰 창은 제목 표시줄과 크기 조절이 있는 일반 창이며 `NSScreen.visibleFrame`을 사용해 Dock/메뉴 영역을 제외합니다.

`PhotoList`는 휴지통 이동 후 다음/이전 선택과 삭제 중 다른 사진으로 이동한 경우의 선택 보존을 담당합니다.
실제 휴지통 이동은 직렬 백그라운드 큐에서 `FileManager.trashItem`으로 수행하며 원래 폴더 접근 lease를 유지합니다.
결과는 파일 URL 및 폴더 세대를 확인해 반영합니다. 키 반복 및 중복 요청은 무시하며 영구 삭제 폴백은 없습니다.

태그는 원본에 쓰지 않습니다. 별도 버전 1 JSON을 직렬 큐에서 읽고 원자적으로 갱신합니다.
UI는 저장 성공 후 URL별 상태를 반영하며 전체 썸네일을 재디코딩하지 않습니다.
저장 위치는 앱 표시 이름/버전과 무관한 `dev.photoselect.app/tags.json` 경로를 유지합니다.
정상 종료 시 AppDelegate가 terminateLater를 반환하고 같은 TagStore 큐의 대기 작업 및 메인 큐 결과가 완료되면 종료를 허용합니다.
이때 새 태그 입력을 막아 종료 대기 요청 뒤로 쓰기가 추가되지 않게 합니다. 디스크 I/O를 메인 스레드에서 기다리지 않습니다.
손상된 메타데이터는 덮어쓰지 않으며 폴더를 바꿔도 저장소 오류 표시를 유지합니다.
파일 경로 기준이며 외부 이름 변경/이동은 자동 추적하지 않습니다. 자세한 동작은 [사용 안내](browsing-tags-trash.md)를 참고하세요.

상단 명령은 macOS 표준 NSMenu의 파일·보기·사진·윈도우 메뉴로 제공합니다. 창의 32pt 도구바와 세 영역은 유지합니다.
사진이 없는 경우 메뉴를 비활성화하고, 메뉴 명령도 기존 사진 이동·태그·휴지통 경로를 사용합니다.
태그/Delete의 메뉴 키 입력은 기존처럼 사진 목록 또는 큰 사진 뷰어에 키보드 초점이 있을 때만 처리합니다.


## 상단바 높이와 데스크탑 재승인

상단 도구 영역은 가로 한 줄, 높이 32pt로 고정하고 상태 경로는 한 줄 말줄임으로 표시합니다.
아래 분할 영역은 남은 콘텐츠 높이를 사용합니다. 작은 화면에서 창을 밀어내던 고정 최소 높이는 사용하지 않습니다.
표시된 창을 최소/기본/중간 크기로 변경해 도구바 버튼의 실제 표시와 세 영역 높이를 검사하고
테스트용 JPEG로 네이티브 캡처를 남깁니다.

데스크탑은 macOS의 desktopDirectory URL로 바로가기를 만듭니다. 폴더 열기에서 다시 허용하면
같은 경로여도 새 FolderLease를 유지하고 실패한 자식 목록과 요청 세대를 갱신합니다.
접근 실패를 빈 폴더로 확정하지 않고 경고로 표시하며, 사용자의 선택/펼침/새로고침에서만 재시도합니다.
화면의 reload/expand 콜백은 재시도를 시작하지 않아 접근 거부 상태의 반복 읽기를 방지합니다.

## 화면과 미리보기 크기

`WindowLayout`은 `NSScreen.visibleFrame`의 논리 포인트를 사용합니다. 메뉴 막대와 Dock을 제외한 영역에
브라우저는 기본 92% 너비·90% 높이(최대 1600×1000pt), 큰 사진 창은 사용 가능 영역 전체 크기로 배치합니다.
큰 사진 창에는 브라우저의 추가 여백을 적용하지 않으며, 화면/배율 변경 알림으로 같은 화면에 맞출 때도 최대 크기를 유지합니다.
창의 최소 크기도 화면 안으로 제한합니다. 모니터 이동·분리·화면 배율 변경 시 현재 창을 사용 가능한 영역에 맞춥니다.
Retina 물리 픽셀 수로 창 크기를 다시 확대/축소하지 않으며, backingScaleFactor는 100% 이미지 확대에만 사용합니다.

폴더 트리는 기본 18%(최대 240pt), 오른쪽 미리보기는 22%(최대 320pt), 나머지는 가운데 목록에 할당합니다.
폭이 작은 화면에서는 양쪽 영역을 줄여 목록에 절반 이상을 배정합니다. 사용자가 지정한 선호 폭이 없으면 이 기본 비율을 적용하며, 지정한 폭은 창 크기가 허용하는 범위에서 유지합니다.
분할선 드래그 시 선호 너비를 갱신하며, 사진 변경만으로 너비를 다시 설정하지 않습니다.
미리보기 NSImageView는 원본 이미지 크기를 intrinsicContentSize로 노출하지 않고 주어진 영역 안에 맞춰 그립니다.
분할 영역에는 선호 너비 제약을 두어 첫 이미지 로드 후 Auto Layout이 임의의 폭으로 바꾸지 않게 합니다.
이미 표시 중인 큰 사진 창에서는 다음 사진을 열어도 사용자가 조절한 창 크기를 유지합니다.

## 정렬과 일괄 이름 변경

정렬 메타데이터는 이미지 디코딩과 분리된 직렬 OperationQueue에서 추출하며 완료된 목록을 한 번 적용합니다. 파일 작업은 별도 직렬 큐·프로세스 잠금·원자적인 복구 기록과 독점 이름 변경을 사용합니다. [대상 범위·태그 처리·복구 방식·검증 기록](file-management.md)을 참고하세요.
