# 동작과 자원 설계

## 스레드와 취소

AppKit 상태 갱신은 메인 큐에서 수행합니다. 폴더 열거/정렬은 사용자 우선순위 전역 큐에서 실행합니다.
사진 표시/프리페치와 썸네일은 각각 최대 2개의 OperationQueue 작업으로 실행합니다.
방향키 탐색 시 이전 표시·프리페치를 취소하고 요청 세대 UUID로 늦은 결과를 배제합니다.
썸네일 재사용 시 작업을 취소하고 URL 및 폴더 세대를 확인합니다. 현재 이미지 완료 후 양옆 1장씩 낮은 우선순위로 프리페치합니다.
이미지 바이트는 디코더 작업 내부에서 읽습니다. 메인 큐는 파일 디코딩을 하지 않습니다.

ImageIO/Core Image의 동기 디코딩이 시작되면 내부 작업을 강제 취소할 수 없습니다.
취소는 작업 시작 전/완료 후에 검사합니다. 빠른 탐색에서도 이미 실행 중인 최대 2개 디코딩 때문에 새 요청이 기다릴 수 있습니다.
폴더 열거 자체도 강제 취소되지 않지만 과거 결과는 반영하지 않습니다.
특히 외장 HDD 지연과 RAW 디코더 지연은 실제 측정이 필요합니다.

캐시는 파이프라인별 192MiB/256항목의 엄격한 LRU 비트맵 예산(합계 최대 384MiB)입니다.
이미지 비용은 bytesPerRow × height. 예산보다 큰 단일 이미지는 캐시에 넣지 않습니다.
현재 표시 이미지, 실행 중인 최대 4개 작업(두 큐 합계), CIContext/시스템 디코더 중간 버퍼와 GPU 메모리는 이 예산 밖입니다.
따라서 프로세스 전체의 메모리 상한을 의미하지 않습니다. 대형 ARW 연속 탐색의 메모리 최고치를 Instruments로 확인해야 합니다.
폴더 전환/새로고침/볼륨 해제에서 캐시를 비웁니다. 파일 변경을 실시간으로 추적하지 않으므로 변경 후 새로고침이 필요합니다.

## Retina의 100%

**원본 이미지 1픽셀 = 디스플레이 물리 픽셀 1개**로 정의합니다.
backingScaleFactor=2이면 원본 6000×4000 이미지는 3000×2000 AppKit 포인트 크기로 그립니다.
따라서 1픽셀=1포인트 방식의 Retina 2배 확대와 다릅니다. 화면 맞춤은 창 포인트 크기를 기준으로 계산합니다.

버튼을 누른 위치를 화면 맞춤 이미지의 정규화 좌표로 변환하고 그 원본 위치가 커서 아래로 오도록 확대합니다.
드래그 위치에 따라 이 좌표를 다시 계산합니다. 가장자리에서는 빈 영역이 나타나지 않도록 이동 범위를 제한합니다.
뷰보다 작은 이미지는 중앙에 위치하므로 가장자리 커서 고정이 제한됩니다.
버튼 해제, 방향키, Esc, 앱 비활성화 시 확대 상태를 해제합니다.
디스플레이 해상도 스케일링과 모니터 이동에 따른 체감 선명도는 Mac 실기기에서 확인해야 합니다.

## ARW 경로와 정확도

1. ImageIO로 속성 및 내장 썸네일/프리뷰를 요청합니다. API가 반환하는 것이 항상 최대 해상도 내장 JPEG인 것은 아닙니다.
2. 내장 이미지가 없으면 ImageIO의 생성 옵션으로 안전한 디코딩을 시도합니다. 손상/미지원이면 오류를 반환합니다.
3. 첫 표시용 프리뷰는 최대 2560픽셀 요청입니다. ARW에 작은 프리뷰만 있으면 작은 이미지를 우선 표시할 수 있습니다.
4. 확대 요청 시 CIRAWFilter로 원본 RAW 기반 고해상도 렌더링을 별도 비동기 요청합니다. 준비 전에는 원본 픽셀 크기에 프리뷰를 확대하며 **확대 정확도 제한**을 계속 표시합니다.
5. 고해상도 실패 시 프리뷰를 유지하고 오류를 표시합니다. JPEG도 첫 표시가 축소본이면 확대 시 원본 크기로 다시 디코딩합니다.

ARW 프리뷰는 보수적으로 항상 프리뷰로 분류하므로 충분한 내장 JPEG가 있어도 확대 시 RAW 렌더링을 요청합니다.
별도 ARW 바이너리 파서/추출 모듈은 도입하지 않았습니다. 시스템 API를 우선 검증한 후 필요성을 판단합니다.
Sony 모든 바디, 압축/무손실/비압축 ARW 변형을 지원한다고 주장하지 않습니다.
지원은 설치된 macOS의 ImageIO/Apple RAW 카메라 지원에 의존합니다. 미지원 ARW는 프리뷰만 가능하거나 아예 열리지 않을 수 있습니다.
RAW와 카메라 JPEG 사이 색/노이즈/선명도 차이가 날 수 있으며, Core Image 기본 렌더링은 카메라 JPEG의 정확한 재현이 아닙니다.
RAW 방향/픽셀 크기와 내장 JPEG 방향의 일치도 실제 카메라별로 확인해야 합니다.

## 파일 접근

NSOpenPanel에서 선택한 루트 URL의 security scope를 획득하고 하위 폴더 작업과 디코딩 작업이 lease를 보유합니다.
폴더를 바꿔도 완료되지 않은 디코딩이 scope를 잃지 않게 합니다. startAccessing 실패가 곧 파일 접근 거부를 뜻하지는 않으므로 실제 읽기 결과를 사용합니다.
macOS 개인정보 보호/TCC 거부나 장치 해제는 읽기 오류로 처리합니다. 예외를 삼키고 성공으로 표시하지 않습니다.
영구 북마크가 없으므로 앱 재시작 시 사용자가 폴더를 다시 선택해야 합니다.
