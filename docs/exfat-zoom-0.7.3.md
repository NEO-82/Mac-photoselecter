# v0.7.3 — exFAT 호환 이름 변경 · 확대 +/- · 시작 시 100%

[Apple Silicon용 v0.7.3 빌드93 DMG](https://github.com/NEO-82/Mac-photoselecter/raw/eb64fc9ed6db6e132ef063de492bf824d8ee450f/downloads/J-S-0.7.3-arm64.dmg)

사용자와 같은 **macOS 27.0.1(26A434), Apple Silicon arm64, Xcode 27.1**에서 실제 exFAT 이름 변경과 재연결 복구를 검증했습니다. 기존 앱 이름·아이콘·Bundle Identifier·tags.json과 RAW/JPEG 표시 경로는 유지합니다. 수정 전 상태 `038d406435b024058ef48fb8d0ffc57f2032e01e`와 복구 브랜치 `checkpoint/v0.7.2-before-finder-rename-and-zoom-keys`를 보존했습니다.

**중요한 보장 범위:** 이미 확인된 목적 파일·폴더·메타데이터 파일 충돌은 거부합니다. J♡S의 조정 규칙을 사용하는 작업은 직렬화합니다. 그러나 exFAT의 커널 독점 rename 미지원은 그대로이므로, **조정에 참여하지 않는 다른 프로그램이 마지막 검사와 이동 사이에 파일을 생성·변경하는 경합까지 원자적으로 차단하지는 못합니다.** 이 조건에서는 덮어쓰기를 완전히 배제할 수 없습니다. 호환 경로를 사용하기 전에 해당 폴더의 Finder 작업·동기화·다른 앱의 쓰기를 끝내야 하며, 실행 창에서 이를 안내하고 명시적인 진행 동의를 받습니다. 취소하면 원본을 변경하지 않습니다.

## 실제 이름 변경 경로

`renamex_np(RENAME_EXCL)`과 `renameatx_np(RENAME_EXCL)`의 exFAT 오류 45는 이 플래그를 지원하지 않는 데서 발생합니다. 일반 이름 변경 자체가 불가능하다는 뜻은 아닙니다. 기존 APFS/HFS+ 경로는 커널 독점 rename을 그대로 사용합니다. 두 API가 실제로 미지원이고 사용자가 호환 동의를 한 경우 **NSFileCoordinator + FileManager.moveItem** 경로로 전환합니다.

1. 같은 부모 폴더와 파일 시스템 장치인지 확인합니다. 다른 폴더·볼륨 이동은 허용하지 않습니다.
2. 별도 검사 파일로 빈 목적 이름 변경, 기존 목적지 충돌 거부, 파일 식별자/내용 유지와 원래 이름 복원을 확인합니다. 검사에 사용자 사진을 사용하지 않습니다.
3. 전체 대상·비대상 이름 충돌, Unicode/대소문자, 선택 범위와 실행 직전 원본 스냅샷을 검증합니다. 고아 `._목적이름` 메타데이터가 있어도 호환 이동을 거부합니다.
4. 호환 작업은 폴더 쓰기를 한 번 조정한 상태에서 UUID 임시 이름 → 최종 이름의 기존 2단계를 실행합니다. 알려진 충돌을 없애려고 기존 파일을 삭제하지 않습니다.
5. 이동 전후 같은 파일 식별자·크기·수정 시간이 유지되는지 확인합니다. 실제 검증한 같은 볼륨 이동은 inode가 유지되는 rename이며, 사진 내용을 복사한 뒤 원본을 삭제하는 구현을 별도로 추가하지 않았습니다.
6. 실제 위치를 확인한 뒤 태그와 브라우저·미리보기 경로를 연결합니다. 실패 시 확인된 원본에 대해서만 롤백하고, 위치/내용을 확정할 수 없으면 태그 갱신과 추측 이동을 중단하고 저널을 보존합니다.

Finder와 같은 이름 변경 결과를 제공하기 위해 공개 시스템 파일 API를 사용합니다. Finder 내부 구현을 역추적하거나 Finder에 Apple Events를 보내는 방식은 아닙니다. 새 자동화 권한이나 외부 라이브러리는 필요하지 않습니다.

## 재연결 저널과 안전 한계

exFAT은 영구 파일 ID를 지원하지 않는다고 보고하므로, 호환 작업은 **버전 2 저널**에 전체 파일 SHA-256·크기·수정/생성 시간과 볼륨·원래/임시/최종 경로를 기록합니다. 기존 버전 1 저널도 계속 읽습니다. APFS/HFS+의 일반 경로에는 새 전체 파일 읽기를 추가하지 않았습니다.

SHA-256은 파일을 1MiB 단위로 읽고, 읽기 전후 동일 원본과 상태인지 확인합니다. 사진 데이터를 새 파일로 복사하거나 수정하지 않습니다. 재연결 후에는 inode에 의존하지 않고 저널 후보 경로의 내용과 메타데이터로 원본을 다시 확인합니다. 읽기 비용 때문에 대용량 RAW 폴더의 exFAT 호환 작업은 APFS보다 느릴 수 있으며, UI에는 이 확인 단계를 별도로 표시합니다.

내용이 변경됐거나, 원본과 같은 내용의 후보가 여러 개이거나, 볼륨·위치를 확인하지 못하면 자동 복구를 중단합니다. 저널은 삭제하지 않습니다. 다른 앱의 비협조적 동시 쓰기, 전원 상실에 따른 exFAT 자체 손상, 물리 장치의 강제 분리 및 모든 메타데이터 오류 조합에 대한 완전한 복구를 보장하지 않습니다. 이 한계는 원자적 RENAME_EXCL 지원과 동일하다고 표시하지 않습니다.

## 확대 키와 재시작 동작

- 확대를 누르고 있는 동안 `+`/`-`로 **10%씩, 100~200% 범위**에서 조절합니다. Shift+`=`, 숫자 키패드의 +/-도 처리합니다.
- 배율만 바꾸며 마우스 좌표·확대 유지 상태·현재 JPEG를 초기화하지 않습니다. 방향키·Delete·태그·놓기·더블클릭·Escape는 기존 흐름을 유지합니다.
- 보기 메뉴는 현재 세션의 선택값을 표시합니다. 앱을 다시 시작하면 항상 **100%**이며 이전 `clickZoomPercent` 저장값은 사용하지 않습니다. 다른 사용자 설정과 태그 파일은 유지합니다.
- 100%는 표시 JPEG와 디스플레이 물리 픽셀의 1:1 대응입니다. 더 높은 배율은 표시 확대이며 RAW 자동 현상·새 미리보기 추출·AI 확대·추가 이미지 캐시를 사용하지 않습니다.

### 이름 변경 시간

| 대상 | APFS | HFS+ | exFAT 호환 |
|---|---:|---:|---:|
| 실제 Sony 샘플 사본 14개, 합계 약 537MB | 21.4ms | 25.6ms | **785.6ms** |
| 소형 시험 파일 1개 | 6.6ms | 18.6ms | 516.8ms |
| 소형 시험 파일 14개 | 9.8ms | 53.6ms | 328.8ms |
| 소형 시험 파일 100개 | 51.3ms | 97.7ms | 1.117초 |
| 소형 시험 파일 1,200개 | **0.675초** | 3.973초 | **11.300초** |

파일 생성·사후 전체 바이트 비교는 시간에서 제외하고, 엔진의 사전 검사·해당하는 SHA-256 읽기·저널·2단계 이름 변경·태그 저장은 포함합니다. 디스크 이미지·따뜻한 파일 캐시의 단회 CI 결과로, 물리 SSD의 보장 속도나 전 버전 대비 개선율을 주장하지 않습니다. 실제 대용량 RAW 1,200장은 별도 측정이 필요합니다.

RAW 탐색 XCTest 프로세스의 최대 RSS는 약 2.34GiB, 측정 시점 RSS는 약 1.28GiB였습니다. 7GiB 호스트의 기존 하드웨어 적응형 캐시 예산 896MiB는 유지합니다. 독립 설치 앱의 정상 상태나 장시간 사용량을 측정한 것은 아닙니다. DMG는 약 3.49MB이며 외부 라이브러리를 추가하지 않았습니다.
